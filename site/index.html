The Proto-Native FHIR R4 Server Built for Speed & Interoperability

Flint is a single-binary, cloud-agnostic HL7 FHIR R4 server written in Go on PostgreSQL. By compiling all 146 FHIR R4 resources directly from google/fhir Protocol Buffers and indexing into 6 static covering tables per tenant, Flint delivers 16× smaller storage, sub-10ms search, and turnkey support for 35+ HL7 Implementation Guides.

Operational OLTP + Optional Analytical Lakehouse

Designed for Both Sub-10ms EHR Point Reads & Population Analytics

Run Flint purely as a zero-dependency PostgreSQL FHIR R4 server, or enable optional streaming CDC into Apache Iceberg and SQLMesh clinical marts.

1. Protobuf-First FHIR R4 Engine

Incoming FHIR R4 JSON is validated against StructureDefinitions, ValueSets, and US Core profiles before being marshaled into compact google/fhir Protobuf wire bytes.

2. HAPI-Style Covering Index Tables

Search parameters are extracted via compiled protoreflect accessors into 6 static covering tables per tenant schema (spidx_string, spidx_token, spidx_date, spidx_reference, spidx_quantity, spidx_uri).

3. Built-In SMART v2 & Audit Trail

Pluggable OIDC/Zitadel and built-in OAuth2 PKCE + Backend Services (ES384/RS384) enforce patient compartment boundaries and record immutable ASTM E2147 / ONC AuditEvent logs.

4. Optional Iceberg + SQLMesh Lakehouse

Enable FLINT_AUTOMQ_BROKERS to stream every FHIR upsert/delete into Apache Iceberg Table Topics and transform into Kimball Patient 360, CMS165, CMS122, and Claims marts via SQLMesh on DuckDB.
